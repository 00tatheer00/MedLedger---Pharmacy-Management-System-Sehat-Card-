## 1. Monitoring Architecture Overview

A resilient healthcare application requires continuous surveillance across three critical pillars:

1. **Liveness & Infrastructure Health:** Application runtime, serverless function health, and PostgreSQL connection pool status.
2. **Clinical Security & Audit Surveillance:** Detecting unauthorized access attempts, repeated authorization failures, and anomalous stock transactions.
3. **Application Performance & Error Telemetry:** Server action failure rates, database query latencies, and uncaught exceptions.

```
+-------------------------------------------------------------+
|                     External Health Probes                  |
```

## 2. Health Check Endpoint (`/api/health`)

MedLedger exposes a production-ready health check endpoint at `/api/health`.

### Response Payload Structure:

```json
{
  "status": "healthy",
  "timestamp": "2026-10-14T01:25:00.000Z",
  "application": {
    "name": "MedLedger",
    "facility": "DHQ Hospital Kohat",
    "status": "online",
    "environment": "production",
    "version": "0.1.0"
  },
  "database": {
    "status": "connected",
    "latency_ms": 14
  },
  "surveillance": {
    "decimal_precision": "integer_paisa",
    "rls_enforcement": "active",
    "audit_logging": "active"
  }
}
```

### Health Check Behavior:

- **HTTP 200 (Healthy):** Application server is responsive and PostgreSQL connection probe succeeds.
- **HTTP 503 (Degraded/Unreachable):** Application server is reachable, but the database connection timed out or rejected queries. External monitors must trigger a high-severity alert.
- **Security Guard:** The health endpoint exposes zero credentials, connection strings, or internal infrastructure IP addresses.

## 3. Privacy & Patient Data Sanitization Rules

Logs generated by MedLedger must adhere strictly to healthcare privacy standards:

### 3.1. Forbidden Log Contents

The logging pipeline and external error trackers must **NEVER** capture:

- Patient full names, Computerized National Identity Card (CNIC) numbers, contact details, or home addresses.
- Medical diagnoses, clinical admission notes, or specific prescribed therapies.
- Authentication tokens (`sb-*-auth-token`), JWT strings, cookies, or service role keys.
- Plaintext passwords or cryptographic seeds.

### 3.2. Approved Diagnostic Information

Logs may capture:

- Standardized error codes (e.g., `FORBIDDEN`, `INVALID_DISPENSING`, `STOCK_EXHAUSTED`).
- Entity IDs (UUIDs) without clinical context (e.g., `prescription_id: 8f4e...`).
- HTTP status codes, execution duration in milliseconds, and request paths.
- Authenticated staff identifier and role (`role: PHARMACIST`).

## 4. Recommended Cloud Monitoring Providers

Since cloud infrastructure is being prepared for DHQ Kohat IT handover, the following industry-standard providers are recommended:

| Capability               | Recommended Provider            | Alternative        | Target Metric / Alert Threshold                                    |
| :----------------------- | :------------------------------ | :----------------- | :----------------------------------------------------------------- |
| **Uptime & Ping**        | Better Stack (Better Uptime)    | UptimeRobot        | Ping `/api/health` every 60s; alert if response != 200 or > 2000ms |
| **Error Tracking**       | Sentry (Next.js SDK)            | Highlight.io       | Uncaught exceptions, server action rejections                      |
| **Database Performance** | Supabase Built-in Observability | Datadog PostgreSQL | Connection pool usage > 80%, query latency > 500ms                 |
| **Log Management**       | Better Stack Logs / Axiom       | AWS CloudWatch     | Audit log stream ingestion & anomaly alerts                        |

> **Operational Notice:** No external monitoring accounts or third-party webhooks are currently provisioned in this repository to prevent phantom telemetry alerts. The application code is architected to accept standard Sentry / OpenTelemetry environment variables (`SENTRY_DSN`, etc.) when provisioned.

## 5. Alerting & Escalation Matrix

| Priority          | Incident Description                | Threshold                                                       | Notification Channel                        | Escalation Path                                                 |
| :---------------- | :---------------------------------- | :-------------------------------------------------------------- | :------------------------------------------ | :-------------------------------------------------------------- |
| **P1 — Critical** | Total Outage / DB Unreachable       | `/api/health` returns 503 or times out for 2 consecutive probes | SMS + Automated Voice Call + Critical Slack | 1. On-Call DevOps<br>2. DHQ Kohat Hospital IT Lead (within 10m) |
| **P2 — High**     | Elevated Server Action Failure Rate | > 5% of dispensing or claim actions fail within 5 minutes       | Slack/Discord `#medledger-alerts` + Email   | 1. Lead Software Engineer<br>2. Pharmacy Supervisor             |
| **P3 — Medium**   | Elevated Database Latency           | Database query roundtrip > 750ms for 5 minutes                  | Email digest to DevOps team                 | DevOps Engineer (next business hour)                            |
| **P4 — Security** | Suspicious Access / Repeated 403s   | > 20 `FORBIDDEN` events from single IP or staff session in 5m   | Instant Security Alert Channel              | Security Officer & IT Audit Directorate                         |
